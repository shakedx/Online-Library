# Project Context

## Состояние проекта

Online Library — учебное приложение с каталогом книг, чтением TXT, личными списками, отзывами и административной страницей. Требования описаны в `docs/SPECIFICATION.md`.

Проект работает на JavaScript. Backend перенесён на Node.js/Express, frontend использует React/JSX, размещение подготовлено для Vercel.

## Стек

- Backend: Node.js, Express, PostgreSQL и `pg`.
- Frontend: React, Vite, React Router, CSS Modules и обычный `fetch`.
- Авторизация: подписанная cookie, CSRF и хеширование паролей через scrypt.
- TXT: локальная папка в разработке, private Vercel Blob в production.
- Тесты: `node:test`, Supertest и отдельная PostgreSQL `online_library_test`.

## Устройство

- `server.js` запускает Express.
- `backend/src/app.js` подключает middleware и маршруты.
- Route-файлы выполняют обычные SQL-запросы через общий PostgreSQL Pool.
- `backend/src/session.js` отвечает за cookie, текущего пользователя, CSRF и роли.
- `backend/src/storage.js` читает и записывает TXT.
- `backend/migrations/001_library_schema.sql` создаёт шесть таблиц приложения.
- `frontend/src` содержит страницы и компоненты React на JavaScript/JSX.

Сложные заготовки удалены: нет ORM, service/repository-слоёв, собственных HMAC-cookie, serverless rate limiter, advisory lock и автоматического распознавания старой схемы. Миграции применяются простым SQL-runner. Неиспользуемые таблицы `auth_rate_limits` и `alembic_version` удалены из локальных development/test БД без изменения данных приложения. Старое Python-окружение и Python-код больше не нужны.

## Поведение

- Каталог, карточки и отзывы публичны; TXT доступен только после входа.
- Регистрация создаёт обычного пользователя. Администратор назначается командой `npm run admin:make -- EMAIL`.
- Администратор управляет книгами и TXT.
- Пользователь имеет по одному избранному, списку чтения и истории без дубликатов.
- Один пользователь оставляет книге один отзыв с обязательной оценкой 1–5 и необязательным комментарием.
- API возвращает JSON-ошибки в едином формате.

## Локальные данные

Development-БД `online_library` сохранена: 4 демонстрационные книги, 2 аккаунта, один из аккаунтов имеет роль admin. Пароли не записаны в коде и документации. Тесты используют только `online_library_test` и очищают данные после каждого теста.

## Тексты демонстрационных книг

7 октября 2026 года четыре существующие карточки наполнены полными текстами произведений из общественного достояния: «Капитанская дочка», «Дубровский», «Шинель» и «Каштанка». Исходные электронные версии взяты с Sheba.spb.ru и TheLib.ru, очищены от рекламных строк, приведены к UTF-8 и сохранены через локальное книжное хранилище. Пути записаны в `books.text_file_path`; сами TXT остаются в игнорируемом каталоге `backend/storage/books`.

Все четыре reader-маршрута проверены в браузере под временным пользователем. Заголовки, авторы, абзацы, длинный текст и прокрутка отображаются корректно. Временный аккаунт и файлы загрузки после проверки удалены.

После наполнения повторно прошли 5 backend-тестов, 10 frontend-тестов, production-сборка, миграции и оба npm audit. Локальный HTTP вернул `health=ok` и 4 книги; в development-БД осталось ровно 2 постоянных аккаунта.

## Размещение

8 октября 2026 года проект опубликован:

- GitHub: https://github.com/shakedx/Online-Library;
- production: https://online-library-liard.vercel.app;
- Vercel-проект `online-library` находится в Hobby-команде `Library`;
- production PostgreSQL работает в Neon Free, регион `fra1`;
- четыре TXT хранятся в private Vercel Blob `online-library-books`, регион `fra1`;
- в production перенесены 2 постоянных аккаунта, 4 книги и существующие личные данные;
- `SECRET_KEY`, `DATABASE_URL` и Blob-токен хранятся только в окружении Vercel.

Для распознавания Express платформой `server.js` напрямую создаёт экземпляр Express и передаёт его в `createApp`. Это не меняет локальную архитектуру и позволяет оставить один и тот же entrypoint для разработки и Vercel Function.

Проверки размещения:

- production-сборка Vercel завершилась со статусом `READY`;
- `/api/health` вернул 200 и `{"status":"ok"}`;
- `/api/books` вернул 4 книги, прямой `/books/1` — React-приложение;
- production E2E проверил регистрацию, вход, HttpOnly cookie, CSRF, чтение private TXT, избранное и отзыв;
- временный QA-пользователь и его данные удалены после проверки;
- локально повторно прошли 5 backend-тестов, 10 frontend-тестов, сборка, обе проверки `npm audit` и `npm run db:migrate`.

Репозиторий `shakedx/Online-Library` подключён к Vercel. Каждый push в `main` запускает production-deploy автоматически; при необходимости ручной deploy выполняется командой `vercel --prod`.
